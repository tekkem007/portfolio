# tekkem007.github.io

Portfolio of **Vishnu Vardhan Tekkem** — 3D Team Lead and Environment Artist, Pune, India.

**Live site:** https://tekkem007.github.io/portfolio/

A static site: no backend, no database, no server-side rendering at request time. Every route is
prerendered to a real `index.html` at build time and served directly by GitHub Pages.

Deployed as a GitHub Pages **project site**, so everything is served under the `/portfolio/`
prefix. Four files carry that prefix and must stay in sync if the repository is ever renamed —
see [Changing the deployment path](#changing-the-deployment-path).

---

## Stack

| Concern      | Choice                                                          |
| ------------ | --------------------------------------------------------------- |
| Build        | Vite 7                                                            |
| UI           | React 19 + TypeScript (strict)                                    |
| 3D           | Three.js — dynamically imported, hero only                        |
| Motion       | GSAP + ScrollTrigger — dynamically imported, scroll reveals only  |
| Styling      | Plain CSS with custom properties (`src/styles/`)                  |
| Routing      | ~90-line path router (`src/lib/router.tsx`) over prerendered HTML |
| Images       | AVIF + WebP + JPEG, generated by `sharp`                          |
| Deploy       | GitHub Actions → GitHub Pages                                     |

No CSS framework and no web fonts: the type is a system stack, which keeps first paint immediate
and removes a network dependency. To swap in a real typeface, self-host it and change
`--font-sans` / `--font-mono` in `src/styles/tokens.css`.

## Local development

```bash
npm install
npm run dev
```

Then open http://localhost:5173.

### Verifying the real thing

`npm run dev` serves the app through Vite, which is more forgiving than GitHub Pages. Before
pushing anything that touches routing or assets, check the production build instead:

```bash
npm run build
npm run serve:dist
```

Then open http://localhost:4173/portfolio/ (a bare `/` redirects there).

`serve:dist` deliberately imitates GitHub Pages rather than a friendly dev server — it mounts
`dist/` under the same `/portfolio/` prefix, directory URLs resolve to `index.html`, a missing
trailing slash 301-redirects, and anything unmatched returns a real 404 with `404.html`.

Serving under the prefix is the point: any URL that accidentally hard-codes a root-absolute path
404s here, before it ships. If a route works here, it works on Pages.

### Scripts

| Script               | What it does                                                        |
| -------------------- | ------------------------------------------------------------------- |
| `npm run dev`        | Vite dev server with HMR                                              |
| `npm run build`      | Type check → client build → SSR build → prerender all routes          |
| `npm run serve:dist` | Serves `dist/` with GitHub Pages semantics on port 4173                |
| `npm run lint`       | ESLint over `src/` and `scripts/`                                      |
| `npm run media`      | Downloads source images and regenerates every optimised derivative     |

## How the build produces static routes

1. `vite build` — the normal client bundle into `dist/`.
2. `vite build --ssr src/entry-server.tsx` — the same React tree compiled for Node into `dist-ssr/`.
3. `scripts/prerender.mjs` — renders each route in `src/routes.ts` to HTML, injects it plus that
   route's `<head>` metadata into the Vite template, and writes a real file:

```
dist/index.html
dist/work/maintenance-hangar/index.html
dist/work/layered-material-system/index.html
dist/work/the-silent-gate/index.html
dist/404.html
dist/sitemap.xml
dist/.nojekyll
```

The client then hydrates that HTML. With JavaScript disabled, every page is still complete and
readable, and every link is a plain `<a href>`.

`.nojekyll` matters: without it GitHub Pages runs the output through Jekyll, which silently drops
files and directories beginning with an underscore.

## Editing content

All copy lives in `src/content/`. Nothing is hard-coded in components.

| File               | Holds                                                              |
| ------------------ | ------------------------------------------------------------------ |
| `profile.ts`       | Name, role, hero copy, About paragraphs, email, social links, SEO   |
| `projects.ts`      | Every project card and the three full case studies                  |
| `experience.ts`    | Work history and the leadership section                             |
| `capabilities.ts`  | Skills groups, the "also familiar with" note, and tools             |
| `types.ts`         | The content model, with the rules each field is bound by            |

### Adding a project

1. Add its images to the `MEDIA` array in `scripts/media-manifest.mjs` (source URL, dimensions,
   and real alt text).
2. Run `npm run media`.
3. Append an entry to `projects` in `src/content/projects.ts`.

It now appears in the grid. Give it a `caseStudy` block as well and it automatically gets its own
prerendered page at `/work/<slug>/`, its own metadata, and a sitemap entry — there is no second
list to update.

### Replacing media safely

Never drop an unprocessed image into `public/media/`. The app reads
`src/content/media.generated.json` for intrinsic dimensions, and an entry that is not in that file
renders nothing at all. Always go through `scripts/media-manifest.mjs` + `npm run media`, which
writes the derivatives and the manifest together.

`media-src/` (the downloaded originals) is gitignored. Only the optimised output is committed —
about 5 MB for 25 images across three widths and three formats.

### Updating the résumé or links

Edit `profile.ts`. The email, social links, résumé metadata, JSON-LD structured data and footer all
read from it.

The published résumé at `public/Vishnu-Vardhan-Tekkem-Resume.pdf` is **generated, not copied**:

```bash
python scripts/build-resume.py
```

The source résumé carries a personal phone number, and this site is public, so the PDF is rebuilt
from the text in `scripts/build-resume.py` with that line omitted. This matters: redacting a PDF by
drawing a box over text leaves the original string sitting in the content stream, fully
recoverable. Regenerating guarantees the number is simply not in the file.

To change the résumé, edit the content in `scripts/build-resume.py` and re-run it. Requires
`reportlab` (`pip install reportlab`). **Do not** drop the original résumé into `public/` — that
republishes the phone number.

## Deployment

The site deploys automatically on every push to `main` via
[`.github/workflows/deploy-pages.yml`](.github/workflows/deploy-pages.yml), which lints,
type checks, builds, and uploads `dist/` as a Pages artifact.

### One-time repository setup

1. The repository must be **public**. GitHub Pages does not publish from a private repository on
   the free plan.
2. Push this repository to `https://github.com/tekkem007/portfolio`.
3. In the repository: **Settings → Pages → Build and deployment → Source → GitHub Actions**.
   (Not "Deploy from a branch" — the workflow publishes the artifact directly.)
4. Push to `main`, or run the workflow manually from the **Actions** tab.

No secrets or tokens are required. The workflow uses the GitHub-provided token with the minimum
permissions it needs.

### Changing the deployment path

The `/portfolio/` prefix comes from the repository name. If the repository is renamed, or moved to
a user site, update these four places together:

| File                         | Change                                                       |
| ---------------------------- | ------------------------------------------------------------ |
| `vite.config.ts`             | `base: '/<repo>/'` (or `'/'` for a user site)                 |
| `src/content/profile.ts`     | `SITE_URL`, including the subpath                             |
| `public/site.webmanifest`    | `start_url`, `scope`, and the icon `src`                      |
| `public/robots.txt`          | The `Sitemap:` line                                            |

Optionally set `BASE_PATH` in `scripts/serve-dist.mjs` (or the env var) to match, so local
verification keeps mirroring production.

Everything else — every asset URL, every internal link, every canonical and Open Graph tag — is
derived from `import.meta.env.BASE_URL` and `SITE_URL`, so nothing else needs touching.

> **Project-site caveat:** crawlers only read `robots.txt` from the domain root
> (`tekkem007.github.io/robots.txt`), which belongs to the user site, not this repository. The
> `robots.txt` shipped here is therefore inert — it is kept for correctness if the site ever moves
> to the root. Discovery relies on the canonical tags and `sitemap.xml`, which are correct.

## Accessibility

- Semantic landmarks (`header`, `nav`, `main`, `footer`), one `h1` per page, no skipped heading levels.
- A skip link is the first focusable element on every page.
- Visible focus indicators via `:focus-visible`; no positive `tabindex` anywhere.
- Every image has real, descriptive alt text written per image — not filenames.
- Body and secondary text measure at least 5:1 contrast against the background (WCAG AA needs 4.5:1).
- Interactive controls are at least 44px tall.
- `prefers-reduced-motion: reduce` collapses every transition and animation, and stops the WebGL
  hero from starting at all.
- Route changes move focus to `<main>` and reset scroll.

## Performance and resilience

- Three.js (~188 kB gzipped) is dynamically imported and never blocks first paint. The initial
  JavaScript payload is roughly 105 kB gzipped.
- The hero scene is skipped entirely on small viewports, touch devices, machines reporting fewer
  than four cores, metered connections, and browsers without WebGL. A CSS fallback renders instead,
  so the hero never looks like something failed.
- The scene renders only while it is on screen and the tab is visible, and it costs two draw calls.
- Images are responsive AVIF/WebP with a JPEG fallback, lazy-loaded below the fold, and always ship
  explicit dimensions — the page does not shift as they arrive.
- **Reveals fail open.** Scroll reveals hide content only after confirming GSAP's ticker is actually
  running. If the frame loop is frozen or throttled, or GSAP fails to load, nothing is ever hidden.
